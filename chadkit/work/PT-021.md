# PT-021 - README Install and Usage; the pyproject for uv tool install

Done 2026-10-22 to the shape [PD-002](../decisions/PD-002-architecture-direction.md) decided. The README's Use
section became Install (the three ways: the one file under `uv run --script`, `uv tool install` from GitHub, plain
Python after `pip install` of the three libraries) and Usage (every command, every option, the conflict markers, the
exit codes, every file with where it lives, every environment variable); its first bullets now say what PG-04 says,
the features people use most, with [docs/features.md](../../docs/features.md) named as where the list is.

[pyproject.toml](../../pyproject.toml) is the install plumbing: name, version 0.1.0, the three dependencies, the
hatchling build backend, the wheel holding only the one file, and the console script `md2gdoc = md2gdoc:cli`. For
that the script's `__main__` block became `cli()`, so the installed command and the file run under Python share the
one line a Google error prints; and the usage line's program name follows the invocation (the file's name when run
as the file, `md2gdoc` as the command). Proven by [PT-021/install.out.txt](PT-021/install.out.txt): `uv tool
install` from the working tree into a scratch tool directory, the command's `--help`, a missing state file as exit
1, a usage error as exit 1, and the file still running under `python3` and `uv run --script`. The GitHub URL form
is the same mechanism and was not run, since this branch is not on GitHub yet.

Decisions taken here: version 0.1.0 and no release process, a version being what `uv tool install` requires and
nothing yet reading it; hatchling as the backend since it ships a single-module wheel from `only-include` with no
other file; `readme` and `license` in the metadata so the wheel carries them, nothing else from the repository.

Not done: a release or tag (none decided); `--json` (PT-026); the three-OS CI that would run the install on Windows
(PT-025).
