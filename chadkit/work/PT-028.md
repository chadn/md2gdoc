# PT-028 `pull` and `sync` stop on a pending suggestion

The task line in [tasks.md](../tasks.md) is the definition.

## Decided

Stop, not warn: the export cannot tell a suggestion from the text, so a file written from it would carry a
reviewer's unaccepted change as content, and the next push would write that content back over the suggestion.
A refusal costs the user one visit to the Doc to accept or reject; a warning costs the reviewer's suggestion.
`init --doc`, the attach, is a first pull and takes the same check. Without the Docs API the command warns and
reads on, as it did before this task. `push` is left as PT-009 built it, the whole replace that drops the
suggestions; PT-029 owns that.

## Measured, 2026-10-27, on the Doc "PT-028 live proof"

[probe.py](PT-028/probe.py), run by [live.sh](PT-028/live.sh) from the evidence folder ([h.py](PT-028/h.py)
puts the script on the path), output in [live.out.txt](PT-028/live.out.txt), the second run, of the shipped text;
the first run's Doc was trashed.

| Question | Answer |
|---|---|
| What the markdown export shows of a pending suggestion | an insertion and a style change as accepted, a deletion as kept: the export cannot tell a suggestion from the text, in either direction |
| Where `documents.get` marks them | under a `suggested...` key on the run, as a list of ids (`suggestedInsertionIds`, `suggestedDeletionIds`) or a map keyed by id (`suggestedTextStyleChanges`); the inserted run carries the same id under both forms, so the count is of distinct ids |
| What the script does | `pull`, `pull --dry-run`, `pull --force`, `sync`, `sync --dry-run` and `init --doc` each refuse with exit 3 and the count; the file is untouched, the attach writes nothing; `--json` reports `suggestions` and `refused_suggestions` |
| Ids in one key, not a list | Google's Document reference declares `suggestedInsertionId` as one string on a list, an inline object, a positioned object and a dropdown; counted as one id, tested against those shapes, not met live |
| A profile that can only view the Doc | not measured: the read names `suggestionsViewMode: SUGGESTIONS_INLINE`, since the default view for such a profile hides suggestions, and that profile gets a 403 on the inline view, both per the [SuggestionsViewMode reference](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents#SuggestionsViewMode); on that 403 the command warns that the Doc went unchecked and reads on, as without the Docs API; against the fake only |
| A Doc with a second tab | not measured: the read is of the first tab, as the edit path's; a suggestion in another tab is not counted |
| `init --doc --dry-run` | makes no call, as before, so it does not refuse; nothing is written either way |
| `push` with suggestions pending | out of scope: the file matched the last sync, so nothing was pushed; a push with a file change takes the whole replace (`why: suggestion`, PT-009) and drops the suggestions |
| Whether the API can resolve one | deleting a suggested insertion's text in the normal write mode cleared that suggestion; a suggested deletion or style change has no such move, so the Doc keeps two, for Chad to accept or reject in the UI |

The Doc stays in Drive with its two suggestions pending, so the refusal can be seen and then lifted in the UI.
