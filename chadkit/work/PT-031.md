# PT-031 - A footer naming the other side

Asked by Chad on 2026-10-28. The only requirements: the path and file, the Doc's URL, and the words `md2gdoc sync`
so a global find lands on every synced file (`md2gdoc sync` rather than `md2gdoc` alone, to miss other mentions);
the date is a sanity check. On by default and kept current; a CLI option leaves it out.

Sample, at the end of the file and of the Doc:

```text
md2gdoc sync last change: YYYY-MM-DD HH:MMam|pm TZ
<path>/<file>.md
<URL_GOOGLE_DOC>
```

Open for the build:

- The footer must not count as a change: the compare and the merge see the text without it, and the sync writes
  it after them. Otherwise every sync reads the last sync's own footer as an edit.
- Which time: the last sync that wrote something, as the sanity check suggests, or the last edit on either side.
- Which path: relative to the repository root, so the same line reads true in every clone.
- Whether the option is remembered in the state file, so a clone's sync does not add the footer back.
