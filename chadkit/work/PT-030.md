# PT-030 - Dogfood the agent flow in this repository

Started 2026-10-28. Before PT-030 this repository's own task Doc, "md2gdoc tasks" from PT-008, had not been
synced since 2026-10-22: the file had changed, the Doc had not (Drive version 24 to 28 with the text unchanged),
and no hook ran the sync. The recipe in [docs/agents.md](../../docs/agents.md) had been checked against the
hooks reference, not against a session. So the daily flow another repository would copy was unproven.

## Installed

`.claude/settings.local.json`, kept out of git, holds the two hooks of the recipe, `SessionStart` and `PostToolUse`
on `Edit(/chadkit/tasks.md)`, with one change: the command runs the repository's own
[md2gdoc.py](../../md2gdoc.py) through `uv run --script`, a sync of the task list, instead of the installed
`md2gdoc`, since this repository is the script and the dogfood should run the code under change. Another repository
uses the recipe as written. The file began as `.claude/settings.json`; the gate on this task found that a tracked
project file would run the sync, against this Doc, at the start of every session on every clone, with a browser login
or an exit 1 for whoever has no token, so it moved to the local file and the recipe now says so.

## What the runs showed

The hooks were installed on 2026-10-28; the first firing seen was on 2026-10-30, and each was seen once:
`PostToolUse` on one `Edit`, `SessionStart` at a context compaction. Not seen: a `SessionStart` at
startup, a `Write`, a conflict (exit 2), a refusal (exit 3), a tick made in the Doc (how `chadkit validate` and
`chadkit doctor` read a `[x]` with no `Completed:` date), and a conflict on a long task line edited on both sides.
Timing: the two syncs by hand of 2026-10-28 took 5.9 s and 3.3 s; no hook run was timed.

- The recipe's `Edit|Write` matcher is what keeps the `PostToolUse` hook to the agent's file tools. `chadkit task
  add` and edits through the shell (`sed`, heredocs) change the task list without firing it, as the runs of
  2026-10-30 show; the next `SessionStart` catches them, or the agent syncs by hand. Untried: a second hook group
  with the `Bash` matcher and `if: "Bash(chadkit task *)"`, a `Stop` hook, a git `post-commit` hook.
- A resolved task, `[-]`, is an open box in the Doc and exports `[ ]` (the Runs table, the state file's `local`
  against its `snapshot`). On a Doc-only change the sync writes the export over the file, so the next edit made
  anywhere in the Doc reopens the task in the file; this repository's task list sits in that state until PT-034
  lands. Beside checkbox lines a `[-]` line also sends every push to the whole replace (`layout`), which no task
  owns.
- The PT-035 line's own `\(` and `\)` came back as `(` and `)`, while its `\+` and `\~` kept the backslash.

Closed 2026-10-30, three days after the start, not the week the task line asked,
on Chad's word. [docs/agents.md](../../docs/agents.md) now says what was seen and what was not.
