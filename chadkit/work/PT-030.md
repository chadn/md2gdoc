# PT-030 - Dogfood the agent flow in this repository

Started 2026-10-28. Before PT-030 this repository's own task Doc, "md2gdoc tasks" from PT-008, had not been
synced since 2026-10-22: the file had changed, the Doc had not (Drive version 24 to 28 with the text unchanged),
and no hook ran the sync. The recipe in [docs/agents.md](../../docs/agents.md) had been checked against the
hooks reference, not against a session. So the daily flow another repository would copy was unproven.

## Installed

`.claude/settings.json`, untracked until PT-030 lands, holds the two hooks of the recipe, `SessionStart` and
`PostToolUse` on `Edit(/chadkit/tasks.md)`, with one change: the command runs the repository's own
[md2gdoc.py](../../md2gdoc.py) through `uv run --script`, a sync of the task list, instead of the installed
`md2gdoc`, since this repository is the script and the dogfood should run the code under change.
Another repository uses the recipe as written.

## To watch

- The `PostToolUse` matcher sees the agent's `Edit` and `Write` tools only. `chadkit task add` and edits through
  the shell (`sed`, heredocs) change tasks.md without firing it; the next `SessionStart` catches them. Whether
  that gap matters, or a `Stop` hook or a git `post-commit` hook fits better, is for the runs to show.
- A tick made in the Doc comes back as `[x]` with no `Completed:` date and no `chadkit task complete` record.
  How `chadkit validate` and `chadkit doctor` read such a line is to be measured on the first Doc-side tick.
- Latency per sync in a hook, against the 60 s timeout in the recipe.
- Conflicts: task lines are long, so a tick on one side and a reword on the other of the same line conflict.
