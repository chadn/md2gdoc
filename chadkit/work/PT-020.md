# PT-020 - Config directory and account profiles

Built in [md2gdoc.py](../../md2gdoc.py) to the shape [PD-002](../decisions/PD-002-architecture-direction.md) decided:
`config_dir()`, `profile_dir()`, `token_scope()` and the rewritten `connect()`, tested in
[tests/test_cli.py](../../tests/test_cli.py) (the `Profiles` case), and run for real on 2026-10-22 under
`uv run --script` with the existing client file and token linked into a scratch profile folder, so no browser
opened: [PT-020/live-run.out.txt](PT-020/live-run.out.txt) is that transcript as printed (paths shortened to
`<scratch>` and `<repo>`). What it shows, in order: `connect()` through the profile folder reads the token's scope
and lists the Docs `drive.file` can see; `--scope drive` against a profile whose token holds `drive.file` is
refused with exit 1; a profile with no client file names the path to save it at, whether named by `--account` or
`MD2GDOC_ACCOUNT`; a full command connects and then fails on the scratch state file's bogus Doc id as one line.
The browser login itself was not run (the same flow as before, now with the profile's paths and the chosen scope).

Decisions taken here:

- The token's scope wins. A run with no `--scope` uses the scope the token was granted; `--scope` matters only at a
  profile's first login. A `--scope` that differs from the token's is an error, not a re-login: a token is granted
  for one scope, so another scope is another profile. The alternative, re-consenting in place, would silently
  widen a `drive.file` profile to `drive`.
- No migration code. A client file or token next to the script is no longer read; the error names the profile
  path to save the client file at. Chad's existing files move by hand (`mkdir -p ~/.config/md2gdoc/default && mv
  client_secret.json token.json ~/.config/md2gdoc/default/`); the `.gitignore` keeps both names so a copy left
  beside the script by habit never lands in a commit, and drops `token-*.json`, which nothing writes now.
- `%APPDATA%` is used only on Windows and only when set; everything else falls back to `~/.config/md2gdoc`, so the
  path logic needs no dependency (PD-002).
- The help names the `pip install` path and the three variables, and says `--scope drive` is for a Doc made by
  hand, under an account that holds little else; the full secondary-account steps stay in
  [docs/setup.md](../../docs/setup.md) marked **To verify** until PT-022 runs them.
- The Service-account setup in setup.md no longer says to save the key next to the script; it has no script option
  (PD-002), so it says outside every repository.

Not done: a live `drive`-scope login (PT-022); README Install and Usage (PT-021); Windows itself untested, the
`%APPDATA%` branch is pinned by a unit test with `sys.platform` patched (PT-025 runs the tests there).
