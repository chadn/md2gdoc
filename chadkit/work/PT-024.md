## Decisions

- Two rules added, the first push-form rule since PT-005: a quote's lines take hard breaks like a paragraph's,
  since without it every alert comes back as a plain quote (run 3); and the normalizer's escape set gains `!`, `$`
  and `\`, since the export escapes them in prose and math is nothing but them. Both measured on run 2. PT-023
  added no rule because its losses were content; these are noise. The escape rule has a cost the Math row names:
  a `\$` a person wrote inside a formula, the math page's way of writing a dollar sign there, comes back without
  its backslash, since the normalizer cannot tell it from the export's own escape (whether the import already
  dropped it is not measured); a `\!` before a link would become an image the same way. Neither is measured
  against Google; the first is pinned in the normalizer's tests.
- Adjacent alerts merging is left as a documented loss, like adjacent lists (10) and padded quotes (10): a
  normalizer rule splitting a quote at an empty `>` line before a marker would be guessing.
- Not pinned: GeoJSON, TopoJSON and STL fences (a fence like mermaid), the two other alert kinds (`[!IMPORTANT]`,
  `[!CAUTION]`, the same syntax), the `` $`...`$ `` math form, section and relative links (links like any), a
  mermaid diagram's rendering (the Doc has no renderer), a fence inside a quote (the new rule would give its code
  lines hard breaks; a fence inside a list item is already an `idea` row), a plain two-line quote that is not an
  alert (the rule's effect on Google's side is measured on alerts alone), a line that lazily continues a deeper
  quote (`> > c` then `> d`: the rule gives no break, since the depths differ, while CommonMark joins them), and
  the HTML the basic page documents beyond `<details>`: `<sub>`, `<sup>`, `<ins>`, `<!-- -->` comments, `<a name>`
  anchors, `<picture>` (fixture 02's HTML import is the nearest evidence).
