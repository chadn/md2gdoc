# PT-006 - The CLI: init, pull, push, status

Built in [md2gdoc.py](../../md2gdoc.py) under the design's "Script design", tested against a fake Drive in
[tests/test_cli.py](../../tests/test_cli.py), and run for real on 2026-10-22 under `uv run --script` on a scratch
copy of fixture 04, with a `token.json` already present so no browser opened:
[PT-006/real-run.out.txt](PT-006/real-run.out.txt) is that transcript as printed (the scratch path shortened to
`<scratch>`; stderr and stdout interleave as the pipe delivered them, so a warning shows before the line it
follows on a terminal), the Doc trashed at the end. The transcript is of the code as committed, re-run after the
gate's findings were applied.

What the real run showed, in order: `init --dry-run` touches nothing; `init` creates the Doc at version 5 and
writes the state file with its five fields; `status` reads both sides; `push` with no change is skipped;
`push --dry-run` prints the diff; `push` replaces the Doc (version 7) and warns that the Doc now holds a blank
line the file lacks (the converter puts one before a list that follows a paragraph line, an `idea` row in
[docs/features.md](../../docs/features.md)); `status` then reads both sides unchanged and a second `push` is
skipped, since the no-op test is against what the file held at the last sync, not the Doc's text; an update made
outside the script, then `status` sees the Doc changed (version 7 to 8), `push` is refused with exit 3, and after
a local edit `pull` is refused the same way; `pull --dry-run` shows what `--force` would write and
`pull --force` writes it, after which both sides read unchanged; a bad command exits 1 with the usage line.

Decisions taken here: `push` exports and compares on every run rather than trusting `version` (PT-004, item 2);
`pull` refuses when the file changed, `--force` overwrites; exit 3 for either refusal, 2 reserved for PT-007's
conflict, 1 for usage, setup and Google errors (a Google error is one line, not a traceback); the state file
holds both normalized texts, the Doc's as the merge base and the file's for the local side, so a converter change
is reported once at push and not as a local edit forever (PLR-20261022-06 finding 1), and no timestamp, so an
unchanged `pull` rewrites nothing; `--account NAME` selects `token-NAME.json`, the borrow from benstein/md2gdoc
(PT-017), with no config directory; `supportsAllDrives` on every Drive call. Not done: the browser login path is
the same code as PT-003's probe but was not exercised from the script; a failed token refresh falls through to it,
untested live; a git hook or CI example for unattended runs. For PT-007: with two texts in the state file the merge
base is `snapshot`, the Doc's; whether `local` is a second base or only the no-op test is that task's call.
