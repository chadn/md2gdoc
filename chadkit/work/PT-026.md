# PT-026 - --json and the agent hook recipe

Built 2026-10-22 to [PD-002](../decisions/PD-002-architecture-direction.md) Users. In [md2gdoc.py](../../md2gdoc.py)
every command now fills one result object and ends in `_finish()`, which prints the prose lines (stdout, then
stderr) or, with `--json`, the one object with `exit`, a fixed `reason` word, `message` (the prose joined) and the
command's fields; `main()` turns a setup or state error raised as a message into the same object with exit 1, and
`cli()` does the same for a Google error when `--json` is among the arguments, since the flag was not parsed yet.
The fields are listed in [docs/agents.md](../../docs/agents.md), which also carries the Claude Code hook recipe:
sync at session start and after every Edit or Write of the file, with what the hooks reference says each exit code
does. Tested in [tests/test_cli.py](../../tests/test_cli.py) (the `Json` case: every command, a conflict, an error,
nothing on stderr, one line on stdout). [PT-026/real-run.out.txt](PT-026/real-run.out.txt) is a real run against
this repository's task list: `status`, a dry sync, a sync that pushed PT-008's completion line (version 24), the
in-sync object, `pull`, and the error object for a file with no state.

Decisions taken here: the prose and the object share one code path, so neither can drift from the other; `reason`
is a closed vocabulary and `exit` repeats the exit code, so a parser needs neither the prose nor the process code;
a usage error stays argparse's prose, since `--json` is read by the same parser that rejected the arguments; the
hook recipe does not pass `--json`, since Claude Code relays a hook's stdout and stderr as text, and the prose
lines are what an agent should read; the hooks reference was read by a guide agent on 2026-10-22 and the one
unverified point, the `if` field's path matching, is marked in the doc.

Not done: the hook recipe was not run in a Claude Code session; the gate checks cannot see the recipe's JSON.
