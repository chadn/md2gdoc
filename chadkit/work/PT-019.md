# PT-019 - Architecture direction

The end state the script is built toward, settled by Chad's answers below (2026-10-22) and recorded as
[PD-002](../decisions/PD-002-architecture-direction.md), which also lists the follow-on tasks. The premise: the
current state is never the end state; the script is made the best version of itself, independent of its history
but informed by it and by single-file Python CLI practice.

## The assumptions found, the question asked, the answer

1. Run from a clone with `uv run --script`, never on PATH: now one downloaded file, also `uv tool install`
   from GitHub; no PyPI.
2. Command name: `md2gdoc`, benstein's clash accepted.
3. macOS only, CRLF declined: now Windows, macOS, Linux with CI on all three, CRLF kept, UTF-8 forced.
4. `uv` required: `uv` documented, `pip install` of the three libraries also works.
5. Client file and token next to the script: now the per-user config directory (XDG, `%APPDATA%`,
   `MD2GDOC_CONFIG_DIR`).
6. State file next to the markdown, committed: kept.
7. `--account` picks a token under one client: kept, plus `MD2GDOC_ACCOUNT`; and Chad added that two client
   files from two Google accounts, one `drive.file` and one `drive`, must switch on the command line, which
   makes a profile a folder holding its own client file and token.
8. `drive.file` only: `drive` added as a per-profile scope for existing Docs, with Chad's recommended way (a
   second or new md2gdoc account, its own Cloud project, Docs shared with it as Editor); service accounts
   documented, not implemented.
9. One file under 500 lines: one file, no target, grows as needed.
10. Prose output for people and agents alike: `--json` on every command; hook recipes as docs.
11. Unattended includes CI: cron and hooks only; CI waits for a service-account path.
12. One file per command: kept for now.
13. Whole-document replace (PD-001): kept, moot once PT-009 lands.
14. The normalizer targets this repository's markdown habits: now GFM, then GitHub.com's platform layer, each a
    fixture task.
15. Exit codes 0, 1, 2, 3: kept.
16. Help names task ids: never in user-facing text.
17. Deliverables: PD-002, a design.md "End state" section, follow-on tasks for code and doc changes larger than a
    sentence; Chad added README Install and Usage sections with every environment variable and file.

Decided by me within those answers: a profile is `<config dir>/<account>/` with `client_secret.json` and `token.json`
inside, the default profile named `default`, the scope chosen at first login by `--scope drive.file` or `--scope
drive` and remembered in the token; the config-directory path logic written without a new dependency; `uv tool
install` needs a `pyproject.toml` with name, version, dependencies and a build system, which is install plumbing
beside the one file, not a package anyone imports. Chad's later instruction, after the gate ran: a decision record
decides the thing, never what the README or a doc says; the README and [docs/](../../docs/) may be rewritten freely,
only log and decision records are stable.
