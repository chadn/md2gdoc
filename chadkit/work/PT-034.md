# PT-034 - The file's side survives a Doc-only change

A _Doc-only change_: a sync or pull where the file has not changed since the last sync and the Doc has. Found
2026-10-29 in use on another repository's file: a file with an HTML comment at its top was pushed, edited in the
Doc, and synced; the comment was gone from the file, and lines the Doc had not touched came back in the export's
shape. The run's output was not kept; the fixture pair below is the evidence to come. Status: open, started
2026-10-30.

## Cause

`cmd_sync` in [md2gdoc.py](../../md2gdoc.py): on a Doc-only change the Doc's export is the result and nothing is
merged; the comment on that line says why, so the converter's own differences between the two texts of the last sync
never read as a conflict. `cmd_pull` and the attach (`init --doc`) write the export over the file the same way. The
price: everything Google's import drops is lost, and every untouched line takes the export's form, a blank line
before a list that follows a paragraph and a code span's trailing space moved out of it (both rows in
[docs/features.md](../../docs/features.md)), and in that run a lazy continuation line indented, which no fixture
shows yet. The normalizer keeps an HTML comment, so the file side had it and the Doc side never did. Two more
cases of the same cause, from PT-030's run on this repository's task list: a resolved task line `[-]` exports as
`[ ]`, so a Doc-only change reopens the task in the file; and a line starting with `<` reads as kind `other` to the
edit path, so every push of a file with a comment line is a whole replace (`structure`).

## Shape

- The file's text is what the Doc's changes are applied to, in both sync and pull: the Doc's hunks against the
  snapshot are carried onto the file's form, so an untouched line keeps the file's shape and a line the Doc did not
  have, an HTML comment, stays where it stood; the converter's differences between the file and the snapshot must
  still not read as conflicts, which is what the shortcut bought. A push carries the file's hunks onto the Doc's form
  the same way, so a file-only change does not push the file's shape of untouched lines.
- Text the Doc cannot hold, an HTML comment, is left out of what goes to the Doc, so it is neither inserted as a
  paragraph nor a reason for the whole replace.
- The footer PT-031 asked for, [chadkit/work/PT-031.md](PT-031.md): three paragraphs separated by blank lines at the
  end of the file and of the Doc (two prose lines in a row send the edit path to the whole replace), stripped from
  both sides before the compare and the merge and written after them; the time is the last sync that wrote either
  side; the path is relative to the repository root; `--no-footer` on any writing command turns it off and the state
  file remembers.
- A fixture pair with an HTML comment pins what the import does with one; the rows in features.md move from
  `planned` to `tested`.

Done when a Doc-only change on a file with an HTML comment and a footer leaves both in the file, a file-only
change pushes the file's hunks and not the file's shape of untouched lines, the fixture pair is in, and the task
list of this repository syncs after a Doc-side edit with PT-031 still `[-]`.
